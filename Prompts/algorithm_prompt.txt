PART 1 — Placement algorithm (/algorithm)
Implement a weighted Maximal Covering Location approach, not a neural
net (deliberately out of scope for this project's timeframe):

- load_data(): parse the CSVs into hospitals (id, lat, lon), census
  units (id, lat/lon centroid, population), and shortage designations
  (MUA/HPSA flags per census unit, from the shapefiles if present).
- build_candidates(): candidate sites = census-tract (or zip) centroids.
- score_candidates(weights, radius_miles=30): for each candidate,
  compute (a) population within radius_miles not already covered by an
  existing hospital within that same radius, (b) average distance
  reduction vs. nearest existing hospital for that population,
  (c) a bonus multiplier if the candidate sits in an MUA/HPSA area,
  (d) a cost proxy from population density (city vs. rural tradeoff).
  Normalize each factor to [0,1] and combine as a weighted sum using
  `weights` (a dict, all four factors, user-adjustable — do not
  hardcode weights).
- get_top_placements(weights, k=5): return the top-k ranked candidates
  as GeoJSON points, each with its total score AND the per-factor
  breakdown (needed for explainability in the demo).
- Optional greedy multi-site mode: after picking the top candidate,
  remove its covered population from demand and rescore, repeating for
  k sites, so placements don't cluster on top of each other.
- Write unit tests for score_candidates with a small synthetic dataset
  (a handful of hospitals + census points) so the scoring logic can be
  verified independently of any real data or the map.
- Expose all of this through a minimal FastAPI (or Flask) app: a single
  endpoint like GET /api/optimize?w_population=&w_distance=&w_shortage=
  &w_cost=&radius=30&k=5 returning a GeoJSON FeatureCollection of
  ranked candidates plus a separate FeatureCollection of existing
  hospitals.
