Project: MedMap — a hospital-placement recommendation tool for TigerHacks26.

CONTEXT
MedMap recommends where a new hospital should be built to reduce driving
distance and lift burden off existing hospitals, using census/population
data, HRSA shortage-area designations (MUA/HPSA), and existing hospital
locations. There is a MapLibre GL JS frontend already started, and the
raw data lives in CSV files (schema not yet documented on my end).

STEP 0 — Explore before building
Look through the project directory and specifically raw. This contains 
all of the data. Describe which of the data is most useful, and if
trying to incorporate it all into the algorithm will make things more complex
and potentially too computationally expensive.

ARCHITECTURE — keep these two concerns fully separate
1. /algorithm — a standalone Python module with NO web/map dependencies.
2. /web — the MapLibre GL JS frontend, which only ever talks to the
   algorithm through a small API (see below). It should never import
   algorithm internals directly.



PART 2 — Map frontend (/web)
Reuse/fix the existing MapLibre GL JS setup. Requirements:
- Hospitals as a GeoJSON source with stable feature ids, rendered as a
  `circle` layer. Fix highlighting by using `map.setFeatureState()` on
  `mouseenter`/`mouseleave`/`click`, with `circle-color` and
  `circle-radius` as data-driven expressions keyed on feature-state
  (`hover`, `selected`) — not by mutating layer paint globally. Add a
  Popup on click showing the hospital's basic info.
- Candidate/optimal-placement points from /api/optimize rendered as a
  distinct layer, colored/sized by score (e.g. a `circle-color`
  interpolation over the score field), with a popup showing the score
  breakdown.
- A toggleable heatmap layer (MapLibre's built-in `heatmap` layer type)
  over population or candidate density, switched on/off via a sidebar
  control — don't add/remove the layer, just toggle its `visibility`
  paint property.
- Sidebar: weight sliders for population / distance / shortage-bonus /
  cost (each 0–1, roughly summing to 1), a radius input, and a
  layer-toggle section (hospitals / heatmap / optimal placements).
  Changing a slider re-calls /api/optimize and re-renders the
  candidate layer — debounce this so it doesn't spam the API on every
  drag tick.
- Legend matching the sketch (hospital marker, candidate marker,
  heatmap gradient).
- Keep this as plain HTML/JS + MapLibre GL JS unless there's already a
  framework in the repo — don't introduce React etc. unless asked.

DELIVERABLE
A runnable local demo: the API server on one port, the static frontend
served separately (or via the same server), with a short README
explaining how to run both, what the CSVs were found to contain, the
exact scoring formula and default weights used, and any assumptions
made about the data.

Work in this order: Step 0 exploration → algorithm module + tests →
API → frontend fixes/build-out. Show me the data summary from Step 0
